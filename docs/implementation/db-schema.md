# Схема базы данных

Родительский индекс: [index.md](index.md) ·
Миграции: `backend/src/main/resources/db/migration/`

Postgres 18, схема ведётся миграциями **Flyway**, применяются при запуске бэкенда.
Поднять базу: см. [development.md](development.md).

## Два сквозных решения

Всё остальное — обычные таблицы. Осмысленного в схеме ровно два места, и оба взялись
из измерений, а не из общих соображений.

### 1. Состояние слова хранится в базе

Поле `word.status`:

| Состояние | Что значит |
|---|---|
| `NO_TRANSLATION` | перевода нет, слово в очереди на разбор моделью |
| `IMPORTED` | перенесено из старого словаря, о корнях сведений нет |
| `AWAITING_REVIEW` | разобрано моделью либо внешним источником, ждёт проверки |
| `COMPLETE` | обработано полностью, включая связь с корнями |

Рядом `last_changed_by` и `last_changed_at` — кто последним трогал слово: правила,
модель, викисловарь или человек.

### 2. У каждого сведения хранится его происхождение

Тип `data_source` стоит почти в каждой таблице:

| Источник | Степень доверия |
|---|---|
| `SOURCE_DICTIONARY` | выписано прямо в старом словаре — достоверно |
| `WIKTIONARY` | викисловарь — достоверно, **требует ссылки** (CC BY-SA) |
| `HUMAN` | проверено человеком — высшая степень |
| `RULES` | выведено нашими правилами — предположительно |
| `LLM` | сказано моделью — требует проверки |

Без этого поля словарь получился бы неисправимым: нельзя ни отличить достоверное от
угаданного, ни понять, что можно безопасно перезаписать.

Особенно это важно для **ударений в словоформах**. Измерено
([word-forms.md](word-forms.md)), что ударение словоформы выводится из
заглавного слова лишь в 16,4 % случаев. Значит:

- 12 746 форм выписаны в старом словаре с ударением — `SOURCE_DICTIONARY`, достоверно
  ([word-forms.md](word-forms.md), «Формы из словаря»);
- остальные породят правила — буквы будут, ударения не будет вовсе;
- заполнять их будет викисловарь (этап 6) и модель (этап 10).

Поэтому у `word_form` источник разделён надвое: `source` — откуда буквы,
`accent_source` — откуда ударение. Буквы вполне могут быть от правил, а ударение —
из викисловаря.

## Таблицы

```
word ──┬── sense ──┬── translation
       │           └── example
       ├── example            (устойчивые обороты: значения у них нет)
       ├── word_form          (поиск по любой форме слова)
       ├── word_root          (русский / праславянский / сербский корень)
       └── discrepancy        (расхождения между источниками)
```

### `word`

Заглавное слово. Каноническая запись — **кириллица со знаками ударения**
(`headword`), рядом лежат `headword_plain` без ударений (по нему ищут) и
`headword_latin`.

`source_key` хранит ключ статьи в исходной базе, чтобы перенос можно было повторить,
ничего не задвоив. `homonym_index` — номер омонима: исходная база пакует омонимы
в одну строку, при разделении заглавные слова совпадут.

### `sense`, `translation`, `example`

Значение, переводы внутри него, примеры употребления.

`sense.number` пусто, если нумерации в исходной статье не было — **а её нет у 72 %
статей**, и разделить их разбором нельзя. У таких всё содержимое лежит одним значением
и ждёт разбора моделью.

`example` ссылается и на слово, и (необязательно) на значение: устойчивые обороты
из блока после `◊` к отдельному значению не привязаны. Отличаются признаком `is_idiom`.

### `word_form`

Главная таблица для поиска. `form_plain` (без ударений) — по нему ищут, поэтому
обязателен; `form` с ударением может пустовать.

Правила дают **несколько правдоподобных вариантов** формы, и какой верен, по буквам
не видно (`бѐдилац → бѐдиоца`, но `ба́јалац → ба́јалца`). Для поиска годятся все, для
показа нужен один — его отмечает `is_preferred`.

#### Когда ударения нет

Пустой `accent_source` означает только «ударения нет». Почему его нет, говорят два поля
(миграция `V3__accent_absence.sql`), и смешивать три случая нельзя: безударное слово с
выдуманным ударением и пробел, выданный за безударность, одинаково портят словарь.

| Случай | Как выглядит |
|---|---|
| слово безударное по природе (`за`, `из`, `и`, `да`, `га`) | `word.unstressed_source` заполнен — кто это установил; перенос ставит `RULES` ([word-forms.md](word-forms.md), «Безударные слова») |
| ударение искали во внешних источниках и не нашли | `accent_source` пусто, `word_form.accent_searched_at` заполнено |
| ударение ещё не искали | `accent_source` и `accent_searched_at` пусты |

Очередь этапа 10 («внешние источники проверены и пусты») берётся частичным указателем
`word_form_accent_not_found_idx`.

`accent_url` — статья, из которой взято ударение (`V4__accent_url.sql`). Для `WIKTIONARY`
обязательна проверкой `word_form_wiktionary_url`: условие CC BY-SA держит схема, а не
договорённость. Как ударение викисловаря попадает в базу —
[wiktionary.md](wiktionary.md), «Запись в базу».

`accent_source` ставится, только если в `form` есть знак тона: одна заударная долгота
(`дēдов` из `de_dov`) ударением не считается. До `V3` перенос ставил `SOURCE_DICTIONARY`
всем 202 заглавным формам без тона; миграция это сняла, перенос больше так не делает.
Ещё 6 «вариантов» заглавного слова словарь повторил вовсе без тона (`ни̏ти, нити`,
`шта̏, шта`, `бо̏ш, бош`) — похоже на запись безударного употребления, не проверено; они
лежат формами `nom.sg.вариант` без источника ударения.

### `word_root`

Связь с русским, праславянским и сербским корнями. `source_url` обязателен для
сведений из викисловаря: он под CC BY-SA.

### `discrepancy`

Когда внешний источник спорит с тем, что уже есть, запись **не затирается** —
расхождение откладывается сюда с обоими значениями и обоими источниками.

Это не роскошь: расхождение между старым словарём и викисловарём означает либо нашу
ошибку разбора, либо разночтение в самом языке (у `vòdi / vȍdi` норма допускает оба
варианта). Молча выбрать одно — значит потерять сведения.

## Указатели

- поиск по началу слова: `word_plain_idx`, `word_latin_idx` (`text_pattern_ops`);
- **поиск по словоформе**: `word_form_plain_idx` — основная задача указателя;
- поиск по русскому переводу: `translation_text_idx`;
- очередь на обработку: `word_status_idx`;
- неразобранные расхождения: `discrepancy_unresolved_idx` (частичный, `where not resolved`).
- ударение искали и не нашли: `word_form_accent_not_found_idx` (частичный).

## Подводный камень Spring Boot 4

Автонастройки в Spring Boot 4 разнесены по отдельным модулям. Одного `flyway-core`
на пути классов **не хватает** — миграции при этом не применяются и **ничего не пишут
в журнал**, приложение просто поднимается с пустой базой. Нужен стартер:

```kotlin
implementation("org.springframework.boot:spring-boot-starter-flyway")
runtimeOnly("org.flywaydb:flyway-database-postgresql")
```
